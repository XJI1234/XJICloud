## 3. 架构与数据流

```mermaid
flowchart LR
  Client["curl / 调用方"] -->|"X-Api-Key"| API["EciInstanceController"]
  API --> Auth["ApiKeyAuthFilter"]
  Auth --> Svc["EciInstanceService"]
  Svc --> DB[(H2 eci_instance)]
  Svc --> Worker["AsyncLifecycleWorker"]
  Worker --> Prov["EciProvider"]
  Prov --> Mock["MockEciProvider"]
  Prov --> Aliyun["AliyunEciProvider"]
  Aliyun --> Cloud["阿里云 ECI OpenAPI"]
```

**职责边界**

- Controller：HTTP 契约与参数
- Service：本地状态权威、幂等删除、触发异步任务
- Provider：只做云侧 Create / Describe / Delete
- Worker：创建后轮询 Running；删除后确认消失；超时写 `FAILED`

### 本地状态机

```
CREATING → RUNNING | FAILED
RUNNING  → STOPPING → TERMINATED | FAILED
CREATING / RUNNING / STOPPING / FAILED + 云侧已删 → TERMINATED（refresh 可回写）
```

### 异步创建时序

1. `POST`：落库 `CREATING`，立即返回本地 UUID  
2. 后台：`create` → 写入 `cloudInstanceId` → 轮询 Describe 至 Running / 失败 / 超时  
3. 调用方用 `GET` / `refresh` 查看进度  

删除同理：先置 `STOPPING` 再异步 Delete；已是 `TERMINATED` 的 DELETE **幂等成功**。

### 进程崩溃与启动补偿

H2 持久化后，进程崩溃可能留下 `CREATING` / `STOPPING` / 非终态任务。启动时 `StartupCompensationRunner`：

1. 无 `cloudInstanceId` 的 `CREATING` → 本地标记 `FAILED`
2. 有云 ID：先 `refresh` 对齐；云侧 NotFound → `TERMINATED`，不再启异步
3. refresh 后仍为 `CREATING` / `STOPPING` → 续跑轮询（`resumeCreatePoll` / `resumeDelete`，不重复 Create）
4. `RUNNING` 只 refresh
5. 非终态任务：关联实例已 `FAILED`/`TERMINATED` → 任务 `FAILED`；其余交 `TaskLifecycleWatcher` 续轮询

运行中：`TaskLifecycleWatcher` 按 `task-poll-interval-sec` 扫描 STARTING/RUNNING，处理云终态自动删与超时。

编排在 Runner，**整批不加长事务**；每条写库独立提交。单条失败只打日志，不阻断启动。

Demo 假定单实例；若日后多节点同时启动会并发补偿，需加分布式锁（本阶段不做）。

## 4. 配置与云凭证

前缀：`eci.`（见 `EciProperties`）

| 键 | 说明 |
|----|------|
| `mock` | 是否 Mock（`true` 不调云） |
| `api-key` | HTTP 鉴权密钥（必填非空）；请求头 `X-Api-Key` |
| `ecs-ram-role-name` | 可选；ECS 实例 RAM 角色名（有则用 InstanceProfile） |
| `access-key-id` / `access-key-secret` | **已废弃**，**不会**用于建阿里云客户端 |
| `region-id` | 如 `cn-hangzhou` |
| `vpc-id` | 可选记录 |
| `vswitch-id` / `security-group-id` | 真实模式必填 |
| `default-image` | 未传 `image` 时使用 |
| `default-cpu` / `default-memory` | 默认规格 |
| `create-timeout-sec` | 等待 Running 超时（默认 300） |
| `delete-timeout-sec` | 等待删除完成超时（默认 300） |
| `poll-interval-ms` | 创建/删除轮询间隔（默认 3000） |
| `default-restart-policy` | 默认 `Never` |
| `default-max-runtime-sec` | 默认 `14400` |
| `task-poll-interval-sec` | 任务终态轮询周期（默认 10） |
| `mock-auto-complete-sec` | Mock 创建后自动终态秒数（默认 3；`<=0` 关闭） |
| `mock-auto-complete-status` | Mock 自动终态（默认 `Succeeded`） |

### 4.0 使用 `.env`（推荐）

在 `eci-manager/` 目录：

```bash
cp .env.example .env
chmod +x scripts/*.sh
./scripts/start.sh          # 真云：.env 中 SPRING_PROFILES_ACTIVE=cloud,local
```

| `.env` 变量 | 映射到 | 说明 |
|-------------|--------|------|
| `SPRING_PROFILES_ACTIVE` | Spring profiles | 真云 `cloud,local`；Mock `dev` |
| `ECI_API_KEY` | `eci.api-key` | `X-Api-Key` |
| `ECI_REGION_ID` 等 | `eci.region-id` 等 | 见 `application.yml` 中 `${ECI_*}` |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` | SDK 凭证链 | **不会**读 yml 的 `access-key-id` |
| `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | 同上 | |
| `ALIBABA_CLOUD_SECURITY_TOKEN` | STS 可选 | |

`scripts/load-env.sh` 在启动前 `source` 即可；curl 测试时也可单独 `source scripts/load-env.sh` 获取 `$ECI_API_KEY`。

**注意：** `.env` 已 gitignore；勿提交含密钥的文件。完整字段见 [`.env.example`](../.env.example)。

### 4.1 两种身份（勿混）

| 身份 | 配置 | 作用 |
|------|------|------|
| 服务 HTTP | `eci.api-key` / 环境变量 `ECI_API_KEY` | 调用本服务的 REST API |
| 阿里云 OpenAPI | **不写 yml AK**；见下方 4.2 / 4.3 | Create/Describe/Delete ECI |

### 4.2 如何配置（按场景）

#### A. 仅本机 Mock（不调云）

1. 默认 `dev` profile（`eci.mock=true`）。  
2. `mvn spring-boot:run`，或 `.env` 中设 `SPRING_PROFILES_ACTIVE=dev` 后 `./scripts/start.sh`。  
3. curl 时 `export ECI_API_KEY=...` 或 `source scripts/load-env.sh`。

#### B. 本机 / WSL 真实调云（推荐：`.env`）

1. `cp .env.example .env`，填写 `ECI_API_KEY`、`ALIBABA_CLOUD_*`、`ECI_VSWITCH_ID`、`ECI_SECURITY_GROUP_ID` 等。  
2. `./scripts/start.sh`。日志应含 `credentialMode=DEFAULT_CHAIN`。  
3. 测完勿将 `.env` 提交 Git。

#### B-alt. 使用 `application-local.yml`（旧方式）

1. 复制模板：

```bash
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
```

编辑 `application-local.yml`（示例）：
eci:
  mock: false
  api-key: <自建强随机串>
  region-id: cn-hangzhou
  vswitch-id: vsw-xxxxxxxx
  security-group-id: sg-xxxxxxxx
  default-image: registry-vpc.cn-hangzhou.aliyuncs.com/eci_open/nginx:1.14.2
  # ecs-ram-role-name:   # 本机不要填；会强制走实例角色而失败
```

2. **在启动 shell 中**设置云凭证（凭证链读取；长期 AK 或 STS 均可）：

```bash
export ALIBABA_CLOUD_ACCESS_KEY_ID='...'
export ALIBABA_CLOUD_ACCESS_KEY_SECRET='...'
# 若是 STS 临时票，再加：
# export ALIBABA_CLOUD_SECURITY_TOKEN='...'
export SPRING_PROFILES_ACTIVE=cloud,local
export ECI_API_KEY='<与 yml 中 api-key 一致>'
```

3. `mvn spring-boot:run`。日志应含：`credentialMode=DEFAULT_CHAIN`（或启动日志里的 `DEFAULT_CHAIN`）。

4. 测完 `unset ALIBABA_CLOUD_ACCESS_KEY_ID ALIBABA_CLOUD_ACCESS_KEY_SECRET ALIBABA_CLOUD_SECURITY_TOKEN`。

> 说明：RAM 角色可以先建好，但**没有可绑定的 ECS 时角色不会生效**；本机只能走环境变量。

#### C. 生产 / 有 ECS（方式 A，推荐）

1. RAM：建角色，授信 **ECS**；自定义策略至少：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "eci:CreateContainerGroup",
        "eci:DescribeContainerGroups",
        "eci:DeleteContainerGroup"
      ],
      "Resource": "*"
    }
  ]
}
```

2. **ECS 控制台** → 目标实例 → **绑定实例 RAM 角色**（角色挂在跑 eci-manager 的机器上，不是挂在 ECI 容器上）。  
3. 部署机 `application-local.yml`（或等价配置）填写 `api-key`、region、vswitch、sg；可选：

```yaml
eci:
  ecs-ram-role-name: <与控制台一致的角色名>
```

也可设环境变量 `ALIBABA_CLOUD_ECS_METADATA=<角色名>` / `ECI_ECS_RAM_ROLE_NAME`。  
4. **删除**部署机上的长期 AccessKey 配置与环境变量。  
5. `SPRING_PROFILES_ACTIVE=cloud,local` 启动。日志期望：`credentialMode=INSTANCE_PROFILE`。

### 4.3 实现说明（开发者）

- `AliyunEciProvider`：有 `ecs-ram-role-name` → `InstanceProfileCredentialsProvider`；否则 → `DefaultCredentialsProvider`（`com.aliyuncs.auth`，与 core 4.7.3 类型匹配）。  
- **不引入** `credentials-java` 直接喂给 `DefaultAcsClient`。  
- 非 ECS 且无环境变量时，链尾探测 `100.100.100.200` 可能 1～2s 超时后启动失败，属预期。

| Profile | 作用 |
|---------|------|
| `dev`（默认） | `mock=true` |
| `cloud` | `mock=false`，推荐阿里云镜像 |
| `local` | 本地网络与 api-key（`application-local.yml`，gitignore） |

真实启动：`SPRING_PROFILES_ACTIVE=cloud,local`

## 5. HTTP 接口（摘要）

完整字段、状态机、错误码、任务 API 与「已实现 / 规划中」标注见 **[API文档.md](./API文档.md)**。

### 约定

- 前缀：`/api/v1/eci`
- 响应：`{ "success": boolean, "message": string|null, "data": ... }`
- 鉴权：`X-Api-Key`（`/actuator/health` 除外）
- 错误：业务异常经 `GlobalExceptionHandler`；缺/错 Key → **401**

### 接口一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/eci/tasks` | 提交任务（`image` 必填），返回多为 `STARTING` |
| GET | `/api/v1/eci/tasks` | 任务列表；`?status=` 过滤 |
| GET | `/api/v1/eci/tasks/{id}` | 任务详情 |
| POST | `/api/v1/eci/tasks/{id}/cancel` | 取消任务（幂等） |
| POST | `/api/v1/eci/instances` | 异步创建实例，返回 `CREATING` |
| DELETE | `/api/v1/eci/instances/{id}` | 删除；已终止幂等成功 |
| GET | `/api/v1/eci/instances?status=` | 实例列表 |
| GET | `/api/v1/eci/instances/{id}` | 实例详情 |
| POST | `/api/v1/eci/instances/{id}/refresh` | Describe 回写本地状态 |
| GET | `/actuator/health` | 存活探测 |

### 行为注意

- 创建：**异步**，勿期望 POST 直接返回 `RUNNING`
- 删除：`CREATING` 中禁止删除（409）；`TERMINATED` 再删仍成功
- `refresh`：云侧已不存在且本地为 `CREATING`/`RUNNING`/`STOPPING`/`FAILED` 时会落到 `TERMINATED`
- GPU 规格按量很贵且依赖库存；测完必须确认任务已终态或 DELETE / cancel
- 任务终态自动删、`maxRuntimeSec` 超时、Mock 自动终态见 [API文档.md](./API文档.md) §3.5

## 6. 使用方法

### 环境

- Linux + JDK 17 + Maven 3.9+
- 若无系统 JDK/Maven：`source ../.tools/env.sh`（仓库便携工具链）

### Mock 联调

```bash
cd eci-manager
source ../.tools/env.sh
export ECI_API_KEY=dev-eci-api-key-change-me
mvn spring-boot:run
```

用真实 UUID 替换路径中的 id（不要写字面量 `{id}`）：

```bash
curl -s -X POST http://127.0.0.1:8081/api/v1/eci/instances \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: $ECI_API_KEY" \
  -d '{"name":"demo-1"}'
```

### 真实联调

完整配置步骤见 **§4.2**。摘要：

1. `cp .../application-local.yml.example .../application-local.yml`，填 region / vswitch / sg / `api-key`  
2. **有 ECS：** 绑 RAM 角色 + 可选 `ecs-ram-role-name`  
   **本机无 ECS：** `export ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`（勿依赖 yml AK）  
3. 启动：

```bash
export SPRING_PROFILES_ACTIVE=cloud,local
export ECI_API_KEY='<与 yml 中 api-key 一致>'
mvn spring-boot:run
```

日志应出现：`ECI provider mode: ALIYUN` 与 `credentialMode=INSTANCE_PROFILE|DEFAULT_CHAIN`。

4. curl 创建（普通或带 `instanceType`/`gpu`）→ 轮询至 `RUNNING` → 控制台核对 → **DELETE** → 确认 `TERMINATED` 且控制台无残留  

> **费用：** 真实实例按量计费（GPU 更高），测完必须删除。

### 常见问题

| 现象 | 处理 |
|------|------|
| `JAVA_HOME is not defined` | `source ../.tools/env.sh` |
| Api-Key 无效 | `export ECI_API_KEY` 与配置一致；勿漏请求头 |
| 一直 Pending / 超时 FAILED | 改用阿里云镜像；检查 NAT/权限/可用区 |
| UUID 转换失败 | 路径里写了字面量 `{id}`，应换成返回的真实 UUID |
| 启动报 vswitch/sg 必填 | 未激活 `local`，或 yml 未加载 |
| 启动凭证失败 / 连 100.100.100.200 超时 | 非 ECS 未设 `ALIBABA_CLOUD_*`（预期）；或 ECS 未绑角色；**yml 里的 access-key 不会生效** |
| 控制台「找不到实例」无法绑角色 | 角色绑的是 **ECS 云服务器**，不是 ECI；无自有 ECS 则用 §4.2 B 环境变量 |
| `OperationDenied.NoStock` | 该规格在交换机可用区无库存；换可用区/规格或稍后重试 |
| yml 写了 AK 仍提示无凭证 | 正常：AK 已废弃；请改为环境变量或实例角色 |
