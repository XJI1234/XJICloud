## 0. 先读：测什么、不测什么

### 0.1 当前已实现、本文覆盖的功能

| 能力 | 路径 / 行为 |
|------|-------------|
| 健康检查（公开） | `GET /actuator/health` |
| Api-Key 鉴权 | 请求头 `X-Api-Key`；错误/缺失 → `401` |
| 手动实例创建 | `POST /api/v1/eci/instances`（`image` 可选，默认 `eci.default-image`） |
| 实例列表 / 详情 / refresh / 删除 | `GET`、`POST .../refresh`、`DELETE`；删除幂等；关闭=删云资源 |
| 实例可选字段 | `name`、`image`、`cpu`、`memory`、`env`、`instanceType`、`gpu`、`imageSnapshotId`、`restartPolicy`、`command`、`args` |
| 任务提交 | `POST /api/v1/eci/tasks`（**`image` 必填**） |
| 任务列表 / 详情 / 取消 | `GET /tasks`、`GET /tasks/{id}`、`POST /tasks/{id}/cancel`（取消幂等） |
| 一任务一实例 | 任务有 `instanceId`；实例有 `taskId`；手动实例 `taskId=null` |
| 状态联动 | 任务 `PENDING`→`STARTING`→`RUNNING`→`SUCCEEDED`/`FAILED`；取消→`CANCELLED`；超时→`TIMEOUT` |
| Mock / 真云 | `eci.mock=true` 不调云；`cloud,local` + 当前钥 STATIC_AK（或空则 RAM/默认链）调真实 ECI |
| 当前云钥 | `GET/PUT /runtime-credentials`；`POST .../test`（草稿或已保存，不改当前） |
| HTTP Api-Key 轮换 | `PUT /credentials/http-api-key`；重叠默认 3600s |

### 0.2 已交付的终态行为（T2–T3）

| 能力 | 说明 |
|------|------|
| 云侧 `Succeeded`/`Failed` 后**自动删实例** | 任务 → `SUCCEEDED` / `FAILED` |
| `maxRuntimeSec` 超时强制删 | `failureReason=TIMEOUT` |
| `TaskLifecycleWatcher` | 按 `task-poll-interval-sec` 轮询 |
| Mock 时间触发 | `mock-auto-complete-sec`（默认 3）后自动迁终态 |

真云模式下任务会在终态后自动删；仍请到控制台确认无残留。手动实例须人工 `DELETE`（云侧 Succeeded 不会触发本地自动删）。

### 0.3 自动化测试覆盖（2026-07-30）

`mvn test` 除 §0.1 契约外，另覆盖：

| 测试类 | 覆盖点 |
|--------|--------|
| `TaskLifecycleWatcherTest` | 钩子 Succeeded/Failed、TIMEOUT、cancel 竞态（Spring IT） |
| `TaskLifecycleWatcherUnitTest` | Never/Always/OnFailure 分支、SUCCEEDED 门闩、describe 异常 |
| `EciTaskLifecycleMockIT` / `EciTaskLifecycleMockFailedIT` | Mock 时间触发终态，无 `simulateStatus` |
| `ManualInstanceNoAutoDeleteIT` | 手动实例云终态后本地仍 RUNNING |
| `StartupCompensationRunnerTest` | 启动任务补偿 TERMINATED/FAILED/RUNNING |
| `EciProviderRestartPolicyTest` | Mock 可注入时钟、自动终态边界 |
| `RuntimeCredentialTesterTest` / `RuntimeCredentialTestApiTest` / `StaticAkRuntimeCredentialProbeTest` | 测通规则、独立 H2 HTTP IT、STATIC_AK factory（**不连真云**） |
| `RuntimeCredentialApiTest` / `HttpApiKeyApiTest` | 当前钥 GET/PUT、HTTP 双钥 |

### 0.4 统一约定

- **服务根地址：** `http://127.0.0.1:8081`
- **API 前缀：** `/api/v1/eci`
- **鉴权头：** `X-Api-Key: <密钥>`
- **成功响应壳：** `{ "success": true, "message": null, "data": ... }`
- **失败响应壳：** `{ "success": false, "message": "...", "data": null }`
- 下文用两个终端：
  - **终端 A：** 启动 / 停服务（占着不关）
  - **终端 B：** 执行 curl / 测试命令

## 1. 一次性环境准备

### 1.1 进入工程目录

打开终端，**必须先进入 `eci-manager` 目录**（不要在仓库根目录直接 `mvn spring-boot:run`）：

```bash
cd ~/XJI/XJICloud/eci-manager
```

确认当前目录有 `pom.xml`：

```bash
ls pom.xml
```

期望：列出 `pom.xml`。

### 1.2 加载本仓 JDK 17 + Maven（解决 `JAVA_HOME is not defined`）

每个**新开的终端**都要执行一次（除非已写入 `~/.bashrc`）：

```bash
source ../.tools/env.sh
```

校验：

```bash
echo "$JAVA_HOME"
java -version
mvn -v
```

期望：

- `JAVA_HOME` 类似：`.../XJICloud/.tools/jdk-17.0.13+11`
- `java -version` 为 **17.x**
- Maven 为 **3.9.x**

若仍报 `JAVA_HOME is not defined correctly`：确认已 `cd` 到 `eci-manager` 且 `source` 路径正确（相对路径是 `../.tools/env.sh`）。

### 1.3（可选）安装 jq，方便解析 JSON

```bash
sudo apt-get update && sudo apt-get install -y jq
```

没有 jq 也可以，下文同时给出「纯 curl + 肉眼看 JSON」的写法。

### 1.4 检查 8081 端口是否被占用

```bash
ss -ltnp | grep 8081 || echo "8081 空闲"
```

若有输出且不是你要保留的服务，结束占用进程（把 `<PID>` 换成 `ss` 里看到的数字）：

```bash
kill <PID>
```

仍不退出时：

```bash
kill -9 <PID>
```

再次确认：

```bash
ss -ltnp | grep 8081 || echo "8081 空闲"
```

常见原因：上次 `mvn spring-boot:run` 未退出，或 Agent/其它会话起的 Mock 仍在跑。报错原文类似：`Port 8081 was already in use`。

### 1.5 配置 `.env`（真云推荐）

```bash
cd ~/XJI/XJICloud/eci-manager
cp .env.example .env
# 编辑 ECI_API_KEY、ALIBABA_CLOUD_*、ECI_VSWITCH_ID 等
chmod +x scripts/*.sh
```

真云启动：`./scripts/start.sh`。curl 前：`source scripts/load-env.sh`（导出 `$ECI_API_KEY`、`$BASE`）。  
字段说明见 [README.md](../README.md) 与 [`.env.example`](../.env.example)。

## 8. 真实云模式（会产生费用）

### 8.1 费用与安全警告

- `eci.mock=false` 会创建**真实**阿里云 ECI 容器组。
- 测完必须 `DELETE` 实例或任务 `cancel`。
- **不要把 AccessKey 或 `.env` 提交进 Git。** `.env` 与 `application-local.yml` 均已 gitignore。
- 云身份：`.env` 里的 `ECI_ACCESS_KEY_*` / `ECI_OSS_*` 是**种子**（current 行不存在才写入）。`ALIBABA_CLOUD_*` 仅 `load-env.sh` 映射到 `ECI_ACCESS_KEY_*`（Java 不读）。成对种子 → 启动日志 `credentialMode=STATIC_AK`。

### 8.2 准备 `.env`（推荐）

```bash
cd ~/XJI/XJICloud/eci-manager
cp .env.example .env
```

用编辑器打开 `.env`，至少填写：

| 变量 | 含义 |
|------|------|
| `SPRING_PROFILES_ACTIVE` | `cloud,local` |
| `ECI_API_KEY` | curl 头 `X-Api-Key` |
| `ECI_ACCESS_KEY_ID` / `SECRET` | ECI 当前钥**种子**（推荐直接填） |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` / `SECRET` | 仅脚本映射：当 `ECI_ACCESS_KEY_*` 为空且无 STS token 时写入种子 |
| `ECI_REGION_ID` | 如 `cn-hangzhou` |
| `ECI_VSWITCH_ID` | 交换机 ID |
| `ECI_SECURITY_GROUP_ID` | 安全组 ID |
| `ECI_VPC_ID` | 可选但建议填 |

镜像建议使用 VPC 内阿里云镜像，例如：

`registry-vpc.cn-hangzhou.aliyuncs.com/eci_open/nginx:1.14.2`

也可选 `application-local.yml`（旧方式），见 §8.2-alt。

## 10. 常见问题

### 10.1 `JAVA_HOME environment variable is not defined correctly`

```bash
cd ~/XJI/XJICloud/eci-manager
source ../.tools/env.sh
java -version
```

### 10.2 `Port 8081 was already in use`

```bash
ss -ltnp | grep 8081
kill <PID>
```

云凭证已 ready 但仍失败时，多半只是端口冲突（日志里可能已有 `ALIYUN client ready`）。

### 10.3 种子、当前钥、`ALIBABA_CLOUD_*` 分别是什么？

- **当前钥**：库表里每种 resource 正在用的那对 AK；GET/PUT `/runtime-credentials` 读写它；启动按它建客户端。
- **种子**：`.env` / `ECI_ACCESS_KEY_*` / `ECI_OSS_*` 只在对应行**不存在**时写入。热切结果不会被下次启动的 `.env` 打回。
- **`ALIBABA_CLOUD_*`**：Java 不读。`load-env.sh` 在 `ECI_ACCESS_KEY_*` 为空且无 STS token 时才映射成种子。
- 成对种子 → `credentialMode=STATIC_AK`。当前钥为空才走 ECS RAM / 默认链。

网络、`api-key`、规格仍可写在 `application-local.yml`。详见 [设计与使用说明.md](./设计与使用说明.md) §4。

### 10.4 真云一直 Pending / 最终超时 FAILED

优先检查：镜像是否 VPC 可拉取、vSwitch 可用区库存、安全组、账号权限。看实例 `failureReason` 与服务日志中的 errCode / requestId。

### 10.5 在仓库根目录执行 `mvn spring-boot:run`

应先：

```bash
cd ~/XJI/XJICloud/eci-manager
```

根目录不是该 Spring Boot 模块的正确工作目录。
