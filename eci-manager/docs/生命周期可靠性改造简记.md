# 生命周期可靠性改造简记

## 改造前

ECI 创建和删除由进程内异步 Worker 长轮询。进程在云侧创建成功、本地保存云实例 ID 之前退出时，可能留下无法关联的云资源；删除失败也缺少跨重启的持续重试。取消任务会先写入 `CANCELLED`，再异步删除实例，因此任务终态不一定代表资源已清理。

## 改造后

| 方面 | 现在的设计 |
|---|---|
| 创建与删除 | 写入 `eci_lifecycle_action`，由 dispatcher 通过租约领取，processor 每次只执行一个云 API 步骤。 |
| 创建幂等 | 本地实例 UUID 同时作为 `ClientToken` 和 Tag，重试使用相同请求标识。 |
| 删除重试 | 失败后持久化错误与下次执行时间，持续退避重试，直到确认 `Deleted` 或 `NotFound`。 |
| 取消语义 | 任务先进入 `CANCELLING`；实例确认 `TERMINATED` 后，动作、实例和任务在同一事务中收敛为终态。 |
| 重启恢复 | 启动时释放过期租约、补齐可恢复的历史动作，一条坏数据不阻断其他记录。 |

## 兼容取舍

P0 之前的 CREATE 没有稳定 `ClientToken` 和本地 UUID Tag，无法安全判断云侧是否已创建资源。这类旧数据保持隔离并要求人工核对，不自动重放 CREATE，以避免重复创建和额外计费。
