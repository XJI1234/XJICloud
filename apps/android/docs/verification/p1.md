已独立执行 13 项真实本机 API 契约检查：注册缺验证码/错误验证码 400、错误验证码被消耗、正确注册 200、重复用户名 409、登录错误密码 401、随后要求验证码、缺验证码拒绝、正确验证码登录成功、用户 Bearer 访问成功、成功后验证码要求重置，以及无效 Bearer 的实际 403。该检查通过真实 HTTP/Redis 完成，未绕过产品校验；它是 API 验证，不等同于客户端 UI E2E。

部署设备测试 `flutter test integration_test/auth_flow_test.dart -d emulator-5554 --dart-define=API_BASE_URL=https://cloud.xji.org.cn --dart-define-from-file=<忽略的测试凭据文件>`：**1 项通过**，真实登录→账号→语言切换→离线帮助→退出→重新登录。首轮脚本等待原生存储初始化不充分，修为等待真实页面状态；另一次根登录页系统返回正常退出 Activity，脚本随后调整顺序。路由守卫/退出后不可返回由受控路由测试及后续普通应用系统操作补测。带测试凭据的 integration APK 不作为交付包，交付使用普通 main 重新构建。

普通 main 的 x86_64 APK（仅 API 参数，无测试凭据）完成了部署登录、强制停止后重新启动恢复账号；切换中文后调整为 1066×1706dp 模拟窗口与系统 200% 字号，操作账号、帮助、开源许可证和退出。退出后物理系统返回关闭 Activity，重新启动仍显示登录页，未回到受保护账号页。窗口、密度、字体设置测试后已恢复。该窗口是模拟 Pad，不冒充物理平板。

随后普通 main 切换本机 API，实际从注册表单输入新账号：错误验证码提示→新验证码刷新→正确验证码注册→提示注册成功并回登录，密码已清空且没有直接进入账号页→显式登录成功。验证码来自本机测试 Redis，仍通过真实 UI/HTTP 提交，不在产品中加入绕过逻辑。

移除设备的本机 API 端口反向映射后强制停止并重启，仍能从安全存储恢复有效会话；没有将不可达网络当作认证失效。测试后恢复映射。受控测试覆盖请求网络失败、并发 401 一次清理、旧 401/成功响应不能污染新会话、JWT exp、持久化写入/删除失败和重试。
