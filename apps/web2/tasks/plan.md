# web2 代码完善计划

日期：2026-10-25。依据：[深度审阅](2026-10-25-web2-review.md)，基线 `63f4f9c`。

## 目标与范围

先保证编辑内容不会写错模型或因普通操作丢失，再修复任务/传输生命周期与本机缓存可靠性，最后补齐必要的交互和门禁。保留现有六个 BC、四层分工、组合根、Result、现有技术栈与浅色产品壳。

本文件保留原实施方案。2026-10-25 已完成 T01–T17 产品实现、自动化回归及二次自审；实际实现取舍、真实验证与外部验收缺口见 [交付报告](2026-10-25-web2-fixes.md)，任务状态见 [todo.md](todo.md)。所有任务限制在 `apps/web2`；未改变后端契约。

## 设计决定

1. Editor 的候选目标与已提交场景分开；只有已成功导入的云端场景才能作为默认覆盖目标。这个不变量放在可独立测试的会话模型/应用命令，Vue composable 管理异步生命周期与呈现状态。
2. dirty 检查是替换场景的前置能力；locale 不应默认触发破坏性重载。无需为此重做 vendor 或桥协议。
3. 异步操作有 owner、取消能力和代次；能取消请求不代表可以省掉迟到结果检查。
4. SSE 使用既有 port 扩展错误/关闭能力，恢复逻辑由应用层协调；不引入第二个网络库。
5. 本机缓存是加速路径，云端 mutation 成功不因缓存异常改成失败；缓存读/失效仍应有可诊断结果和防旧数据策略。
6. 缓存 namespace 属于基础设施与账号组合，不把 OPFS 细节带到 domain 或页面。
7. 不增加全局业务状态库、全局上传任务中心、通用 repository 基类或新一套测试框架。

## 任务明细

### T01：提交成功后才切换可覆盖目标（P1，R01）

**范围 M，约 4–5 文件。** `features/editor/domain/entities/editor-session.entity.ts`、`presentation/SuperSplatEditorView.vue`、聚焦的会话 composable/测试、`application/use-cases/editor.usecase.ts` 及其测试按实际复用控制文件数；若需扩展多个文件，拆出“会话模型与测试”前置小改动。

- 将准备加载的 candidate、已载入的 committed scene、覆盖目标分开，失败不提交候选 ID。
- 保存命令从已提交会话派生目标，并验证 scene/target 一致；覆盖不由 picker 或 URL 单独授权。
- 回归：打开 A→B 下载失败/ready 失败/导入失败，保存不能覆盖 B；快速 A/B 选择的旧结果不能改变当前会话。

**验证：** Editor 组件按钮路径 + 用例不变量测试；真实 SuperSplat 手工重现失败后保存。依赖：无。

### T02：替换编辑内容前统一保护未保存修改（P2，R02）

**范围 M，约 3–4 文件。** Editor 会话 composable、Editor view、Editor 行为测试、必要的 locale 文案。

- 所有替换入口调用统一许可流程：空白、本地文件、云模型、历史预览、语言切换、离开页面；dirty 超时不能静默当作“无修改”。
- 优先保持当前 iframe 场景并延后应用新语言；若已有可用运行时能力则复用。需要重载时先确认丢弃。
- 回归：用户取消上述任一操作后，场景、覆盖目标与路由保持一致；确认后仅执行一次替换。浏览器检查 vendor 已有的 beforeunload 与宿主逻辑，避免新增重复提示。

**验证：** mock bridge 组件交互测试；真实编辑后逐项取消/确认。依赖：T01。

**检查点 A：** P1 错误覆盖与 P2 场景切换均有回归测试；走真实编辑、失败加载、取消离开、再保存路径；pnpm test:web2/build:web2 与自我 Review。不能用 mock 导出成功代替真实编辑验收。

### T03：路由变更与 iframe 导航进入同一生命周期（P2，R12、R10 导航部分）

**范围 M，约 3–4 文件。** Editor view、会话 composable、组件测试，必要时独立导航 helper。

- 监听 query modelId 或使用 onBeforeRouteUpdate，进入 T01/T02 的场景切换事务；内部 replace 不重复打开已提交场景。
- iframe load 等待具备截止、取消与监听清理；卸载/新请求使旧操作失效，不用 fullPath key 强制销毁来掩盖问题。
- 回归：前进/后退、移除 modelId、快速 A/B、load 永不触发、卸载后 load 到达，均不能卡死或提交旧内容。

**验证：** RouterView + memory router 组件测试、假计时器；浏览器前进/后退与资源失败。依赖：T01/T02。

### T04：Editor bridge 保证 Result 与清理契约（P2，R10）

**范围 M，约 2–3 文件。** `infrastructure/post-message-editor.bridge.ts`、新的桥接行为 spec、需要时调整 Editor port。

- File.arrayBuffer、postMessage、超时路径都映射为 Result；所有 settle 分支移除计时器和监听。
- 检查 origin/source 与必要 payload 字段，保留已有安全校验；按现有协议单请求串行或明确关联，避免多个请求互相接收响应。
- 回归：文件读取拒绝、postMessage 抛错、无响应、卸载/取消、非可信消息、正常导入导出。

**验证：** 独立 bridge 测试用假时钟/假窗口；真实导出一次确认协议未回归。依赖：无，可在 B 阶段先做。

### T05：退出/401 先正确清理账号作用域（P2，R09）

**范围 M，约 4–5 文件。** Auth use case/测试、`app/create-container.ts`、HTTP client/测试；若同时触及退出 UI，将其作为单独的小变更。

- 在身份消失前捕获/清理当前账号 active project，通知 workspace，保留最近工程。
- HTTP unauthorized 只使发起请求的同一会话失效，迟到旧 401 不清新会话；取消/失效能力与账号作用域保持一致。
- 检查编辑器 dirty 取消退出时身份不被提前清除；若需要修改 CloudLayout，与 T02 的许可流程衔接并单独验收。

**验证：** 真实 storage/组合根测试：logout、401、重新登录、旧响应；浏览器退出取消与重新登录。依赖：核心无；编辑器退出确认依赖 T02。

### T09：缓存降级不歪曲服务器结果（P2，R05）

**范围 S，约 2 文件。** `http-model-asset.repository.ts` 及其 spec。

- list/get 缓存异常按 miss 走网络；delete/export/restore 已成功时不返回整个操作失败。
- 清理失败时防止后续命中过时缓存；显式缓存管理失败仍返回错误，诊断不泄露 token/签名 URL。
- 回归：OPFS 拒绝、损坏索引/文件、清理失败、正常命中、版本更新后不返回旧字节。

**验证：** repository contract 测试，覆盖网络调用次数与返回结果。依赖：无。

### T10：本机缓存按账号隔离（P2，R06）

**范围 M，约 3–5 文件。** OPFS adapter、组合根、相应 spec，必要的缓存 port 参数。

- 下载开始时捕获 owner；切换身份后旧操作不能写入新账号 namespace。旧全局缓存采用明确的隐藏/清理规则。
- 回归：A 缓存→退出→B 设置列表为空；B 删除不影响 A；回到 A 按保留策略可见。

**验证：** fake OPFS/组合根测试；真实浏览器连续两账号。依赖：T05/T09。

- 回归：并行 put/put、put/remove、索引写入失败；不能只使用“碰巧不并发”的测试。

**验证：** 确定性交错测试 + 真实 OPFS 双 Tab；缺少锁能力时验证声明的降级策略。依赖：T09/T10。

**检查点 C：** 账号条目隔离成立；缓存不可用时仍可下载；云端写成功不被误报；完整测试/构建与 Review。

## 每项变更的共同完成标准

- 最小 diff；只触及对应 BC 与必要通用组件，不混入重命名、样式重构、依赖升级或旧包清理。
- 用回归测试表达用户结果或领域不变量，先复现问题，再验证修复；mock 仅在外部 port/时钟/网络/存储边界。
- 执行 `pnpm test:web2`；UI/构建路径同时执行 `pnpm build:web2`，真实浏览器操作有记录。做不到的明确写“未做浏览器 E2E”及原因/剩余风险。
- 对本次 diff 做缺陷/安全/回归/测试缺口 Review，High/Critical 修完才交付。审阅任务本身不等于这些修复任务已完成。
- 改变会话/port/账号缓存语义时，同步 web2 架构说明；不扩大到无关文档或包。

## 最终验收路径

| 用户路径 | 最少要证明的结果 |
|---|---|
| 登录→打开工程→退出→换账号 | 当前工程正确重置、最近工程仍归属各账号、缓存列表不串号 |
| 上传模型→切 Tab/取消→回列表 | 没有失控传输、旧回调、错误成功提示；complete 边界按真实状态显示 |
| 上传图片→任务观察→断网→恢复 | 进度状态可理解；恢复后拿到任务真实终态；停止后不重连 |
| Editor A→B 失败→保存 | 绝不覆盖 B；错误信息与已载入场景一致 |
| 编辑→新建/本地打开/选云模型/语言切换/离开 | 取消均保留修改，允许丢弃后才替换 |
| Editor 前进/后退→历史预览→覆盖/另存 | URL、已提交会话、保存目标一致；旧响应不能重新提交 |
| 缓存故障→下载/删除/恢复版本 | 云端结果准确，缓存故障降级且不回读旧内容 |
| 两 Tab 并行缓存→删除→刷新设置 | 索引不丢项、不复活删除、不遗留不可管理条目 |
| 全程只用键盘打开/关闭弹层 | 焦点不穿透，返回正确触发点，等待中不能误操作背景 |

## 延后项与开始条件

浏览器大模型内存优化先测量峰值与时间；缓存限额/LRU 先观察真实使用量与配额错误；依赖清理先确认实际引用与构建收益。没有证据时不开展批量性能重写、全量 schema 化、类实体迁移或目录重构。
