## 结论

现有四层 DDD 结构值得保留。主要欠缺是编辑会话的一致性、异步任务生命周期、实时连接恢复和本机缓存的隔离/容错，而不是目录不够多或组件不够小。发现 1 项 P1、12 项 P2；另有架构门禁与契约测试的改进建议。P1 优先处理，P2 按用户路径分批修复。

本文记录首次审阅与规划时的状态，当时未修改产品实现。配套实施方案见 [plan.md](plan.md)，当前执行清单见 [todo.md](todo.md)。

P1 表示可导致错误云端写入；P2 表示可靠性、隔离、交互或资源管理缺陷。没有把未验证的猜测列成 Critical，也没有将测试通过等同于云端功能验收。

## 工程与 DDD 模型理解

平台是 pnpm + Spring Boot monorepo。用户上传图片数据集到 OSS，经后端/Redis/GPU Worker 产生训练结果；PLY/SPZ 模型上传及编辑产物走后端本地盘。当前 Web 产品为 `apps/web2`，查看器采用 Native3DGS WebGPU，高级编辑由 SuperSplat iframe 承担。用户、管理员、Worker JWT 各有独立角色语义。

| BC | 业务对象/规则 | 主要用例 | 外部边界 |
|---|---|---|---|
| Identity | UserSession、Captcha、验证码策略 | 登录、注册、退出、访问导航 | AuthRepository、SessionStore |
| Project | Project、最近访问、当前工程 | CRUD、打开工程、最近工程 | ProjectRepository、WorkspacePersistence |
| Model Asset | ModelAsset、版本、分片范围、缓存修订 | 上传、下载、删除、恢复版本、缓存管理 | ModelAssetRepository、CloudModelCachePort |
| Dataset Training | 归档、manifest、TrainingJob、终态策略 | 提交数据集、观察任务、取消/删除 | TrainingJobRepository、JobEventPort、ObjectStoragePort |
| Viewer | ViewerConfig、模型摘要 | 打开本地/云端模型、配置读写 | ViewerStoragePort、Native3DGS 引擎适配 |
| Editor | 编辑会话、导入/导出、云端保存 | 打开场景、覆盖/另存、版本预览 | EditorBridgePort、ModelAssetRepository |

仓库 frontend-ddd skill 的核心是分开数据生产、运行时编排和视图消费；外部 DTO 经 mapper 防腐，业务规则向内依赖，Vue 负责呈现和交互。web2 已有这些基础：组合根集中在 `create-container.ts`，domain 基本保持纯函数，repository/use case 使用 Result，跨 BC 通过端口和 composable 组合。

最明显的模型缺口是 Editor：当前 `selectedModelId` 同时表示“用户准备打开的模型”和“iframe 已经成功载入、允许被覆盖的模型”。这两个时刻并不相同。补上这个不变量的价值，高于给每个简单 Project CRUD 增加 aggregate/class/factory。

Vue 方面整体使用 Composition API、`script setup`、TypeScript，路由按页面懒加载。Viewer 已实现请求代次、AbortSignal、保留已提交场景等机制，可以在同类问题上参考；无需复制一套新状态框架。

### R01：覆盖目标必须来自已提交场景

位置：`src/features/editor/presentation/SuperSplatEditorView.vue:246`、`:136`、`:378`；`src/features/editor/application/use-cases/editor.usecase.ts:52`。

触发：先成功打开 A，再选择 B，令 B 下载失败，然后选择“保存到云端/覆盖”。`selectCloudModel` 在下载前就写入 `selectedModelId=B`；失败返回后 iframe 仍是 A，`canSaveToCloud` 又恢复可用，默认覆盖目标来自 B。探针实际通过按钮操作确认：只导入过 A，保存命令参数却是 B。

影响：错误覆盖云端模型。后端版本历史可能提供恢复机会，但不能消除错误写入。

最小修复：区分 candidate 与 committed scene；下载、iframe ready、导入确认全部成功后才提交目标身份。失败保留上一个完整会话或转成明确不可覆盖状态。覆盖用例校验已加载会话与目标一致，不能只信 UI 中的模型选择 ID。

验收：A→B 失败后覆盖只能指向 A，或明确禁止保存；快速 A/B 选择、晚完成、导入失败均不能改写错误目标。

### R02：所有破坏性场景切换共用 dirty 保护

位置：`SuperSplatEditorView.vue:237`、`:307`、`:458`、`:576`、`:609`。

目前只有离开路由调用 `editor.isDirty`；语言 watcher 会下载原云模型/重新导入原本地文件/新建空场景，以上操作都尝试重建 iframe。探针确认更改 locale 会再次下载/导入 A，宿主 dirty 查询次数为 0。打开空白、新本地文件、另一个云模型、历史预览也未先协调宿主会话。离页 dirty 查询出错时宿主当前逻辑直接允许离开。

补查 `vendors/supersplat/index.js` 发现 iframe 内已有基于 scene.dirty 的 beforeunload 提示，这是实际缓解措施。因此本项不认定“真实浏览器必然无提示丢修改”，降为 P2。确认的问题是语言变化主动尝试重新加载原始场景，且宿主在浏览器确认之前可能已改写选择身份，没有处理用户拒绝 iframe 导航的事务回滚。真实原生提示的取消效果与 load 等待是否结束仍需浏览器验证；jsdom 探针不覆盖它。

最小修复：将“允许替换当前编辑内容”设为所有入口的前置条件；查询失败给明确提示/用户选择。语言切换优先使用现有 iframe 能力；若没有运行时切换协议，就保留当前编辑场景并提示下次打开应用语言，或确认后重载。不要为此修改预编译 vendor，也不要重复新增其已有的 beforeunload；需要验证原生提示与宿主事务的配合。

验收：有修改时取消新建/换文件/换模型/历史预览/语言切换/离页，场景和目标保持原样；检查 dirty 超时和用户确认丢弃分支。

### R03：实时连接有失败与关闭状态

位置：`src/features/dataset-training/infrastructure/adapters/fetch-job-event.adapter.ts:26`、`:35`、`:46`；`application/job-watch-hub.ts:65`。

网络异常、非 2xx、读流/解析异常只 console.error，正常 EOF 直接退出。hub 不知道连接已死亡，Map 仍保留 jobId；再次 watch 被 has 检查跳过。手动刷新列表也不先移除这个占位，运行任务可能一直停在旧进度。SSE 401 也没有走组合根的会话失效处理。

最小修复：扩展既有 JobEventPort，暴露错误/关闭及连接状态；hub 负责释放占位、有限退避重连或轮询回补；401 复用会话失效策略。重连后先拉快照，避免断线期间终态丢失。unsubscribe 必须终止重连与读流。无需更换 HTTP/SSE 框架。

### R04：清空是异步代次边界

位置：`application/job-watch-hub.ts:48`、`:78`；`presentation/TrainingJobPanel.vue:47`、`:73`、`:85`。

终态事件触发的 getById 在 clear 之后仍无条件 upsert。探针让请求延迟、先 clear 再返回，旧任务确实重新出现。页面列表请求同样没有 alive/request generation 检查：切换 Tab 导致组件卸载、清理订阅后，旧 list 返回仍可 replaceAll/watch。重复刷新还可能用旧快照覆盖更晚的状态。

最小修复：hub 使用 epoch 区分清理前后；页面加载使用项目 ID + 请求代次，unmount 失效，必要时取消。订阅归属保持明确，不能仅取消事件流而放任其衍生请求提交。

### R05：缓存故障不应改变已知的云端结果

位置：`src/features/model-asset/infrastructure/repositories/http-model-asset.repository.ts:31`、`:147`、`:168`、`:266`、`:285`。

writeCached 已容错，但 readCached 的 list/get 及 dropModelCache 的 list/remove 未作同等处理。探针分别确认：OPFS list 抛错时完全不尝试网络下载；服务端 DELETE 已成功时缓存清理异常导致 repository 返回 error。上传 export 和恢复版本也共享此问题，可能诱发用户重复提交。

最小修复：缓存读取异常降级为 miss；服务器 mutation 成功与本机清理结果分开。清理失败时让相应模型缓存失效/被绕过，防止返回旧内容；显式缓存管理页面仍应报告删除失败。不能简单把所有异常吞成成功。

### R06：账号隔离覆盖本机模型缓存

位置：`src/features/model-asset/infrastructure/repositories/opfs-model-cache.ts:4`；`domain/services/model-cache.service.ts:3`；`src/app/create-container.ts:55`；`presentation/SettingsView.vue:24`。

目录固定为 xjicloud-model-cache，key 只有 modelId/versionId，listCached 不按用户过滤。退出不会清除或切换命名空间。因此 A 下载过模型后，B 在同一浏览器登录并打开设置，就会读到 A 的缓存名称、时间和大小，也可删除这些条目。

最小修复：在基础设施/组合根绑定当前用户命名空间；缓存保留策略与账号隔离分开处理。旧无归属缓存不能自动展示给新账号。请求开始时捕获账号作用域，避免下载结束时使用已切换的身份写缓存。

这是应用层本机缓存隔离问题；本轮没有证明后端模型接口存在越权，也不将同源浏览器文件存储承诺为操作系统级安全隔离。

### R07：OPFS 索引变更需串行或事务化

位置：`opfs-model-cache.ts:68`、`:85`、`:94`。

put/remove 都 readIndex→修改快照→writeIndex。两个并行 put 可都读取旧索引，然后后写覆盖前写。探针用两个同时读取旧索引的确定性交错确认：写出两个 bin，list 仅返回一个。remove 与 put 并发还会复活已删除索引。

最小修复：选择已有平台可支持的串行/事务策略；单实例队列只解决当前实例，多 Tab 仍需 Web Locks 或等效跨文档协调。blob 与索引失败之间提供可恢复策略。无需引入完整新缓存框架。

### R08：上传流程有明确的离页归属

位置：`presentation/ModelUploadPanel.vue:93`、`:199`；`src/features/dataset-training/presentation/DatasetUploadPanel.vue:61`；`application/use-cases/submit-dataset.usecase.ts:13`；`infrastructure/adapters/xhr-object-storage.adapter.ts:6`；`src/features/project/presentation/ProjectListView.vue:86`。

模型面板只在 projectId watcher 中 abort，没有卸载清理。探针创建真实上传操作后卸载组件，传给用例的 signal 仍未 aborted。UploadView 的 Tab 用 v-if 切换，因此卸载是现有正常路径。数据集用例/OSS port 没有取消参数；旧上传完成还会向全局 jobWatch upsert/watch。项目页另有一套未传 signal 的上传入口。

最小修复：先明确当前页面上传在离页时取消/确认的策略，并覆盖 Tab、路由与退出；沿既有 port 透传 AbortSignal，清理 XHR；回调提交前检查请求/会话代次。若以后明确需要后台上传，再提升生命周期到应用服务，当前不应自动引入全局任务中心。分片重试/complete 阶段也要遵守取消状态，不能仅在外层循环开头检查。

### R09：失效顺序要保留清理时所需的账号

位置：`src/features/identity/application/use-cases/auth.usecase.ts:59`；`src/app/create-container.ts:31`；`src/features/project/infrastructure/repositories/local-workspace.persistence.ts:50`。

logout 和 unauthorized 均先 session.clear，再调用依赖 session.userId 的 setActiveProjectId(null)。此时 getUserId 返回 null，清理直接 return，且不发 workspace 通知。真实 storage 探针确认旧账号的 active-project key 残留。

最小修复：清理时显式捕获账号，或在身份清除前完成正确作用域的 reset；最近工程按现有产品规则保留。退出确认应在清身份前完成，避免编辑器拒绝路由离开后用户停在已清身份页面。后续 HTTP 失效回调要校验请求所属 session，避免旧 token 的迟到 401 清除新会话；该迟到 401 分支属于源码审阅项，未在本轮单独动态复现。

### R10：Editor port 的异常与生命周期要闭合

位置：`src/features/editor/infrastructure/post-message-editor.bridge.ts:132`、`:141`、`:169`、`:251`；`SuperSplatEditorView.vue:84`。

File.arrayBuffer 失败在 importLocal 中直接 reject，探针已确认调用方拿不到约定的 Result。postMessage 同步抛错同样可能使 promise reject 且清理不到监听/计时器。页面 navigateEditor 只等 load 事件，没有超时、失效或卸载清理；load 永不到达时页面 loading 一直无法结束。bridge 已有 ready/import/export 的局部超时，不能因此认为前置导航也有保护。

最小修复：在基础设施边界映射异常为 DomainError/Result，确保单次 settle 和 cleanup；导航具备超时/取消；组件用 finally 恢复 busy，旧操作不再操作新会话。postMessage 继续保持现有 origin/source 检查。

### R11：按实际支持的格式建立归档不变量

位置：`src/features/dataset-training/domain/services/dataset-archive.service.ts:23`。

白名单未命中时仍接受任意 image/*；image/gif、image/svg+xml 等会进入训练上传。探针确认 GIF 成功归档为 0001.gif。UI/领域错误和工程文档承诺 JPG/PNG/WebP，前端目前违背该能力边界。

最小修复：统一扩展名/MIME 判定与显式允许范围；保持 JPG/JPEG/PNG/WebP、空 MIME 和大小写的合法支持。不要为了修复此项扩大训练格式支持。manifest 缺失是否应阻止 complete 可补契约测试，但当前后端确实将 manifest.json 放入 uploads，本轮不将它列为已发生的契约缺陷。

### R12：同一路由更新要驱动会话事务

位置：`SuperSplatEditorView.vue:217`、`:591`；对照 `src/features/viewer/presentation/LayerViewerView.vue:122`。

Editor 仅在 onMounted / refreshModels 读取 modelId；没有监听 query modelId，也没有 onBeforeRouteUpdate。Vue Router 会复用组件。探针从 A 路由改到 B，URL 是 B，标题与 iframe 仍是 A，未发 B 的下载。浏览器前进/后退可触发这一情况。

最小修复：路由输入进入 R01 的同一场景切换事务，配合 R02 dirty 确认；内部 router.replace 不重复加载已提交场景，避免循环。不要用 fullPath key 强制重建整个编辑器来绕过状态建模。

### R13：模态交互应包含键盘行为

位置：`src/presentation/components/AppSheet.vue:96`、`:139`；`WaitOverlay.vue:75`。

组件渲染 role=dialog / aria-modal=true，但没有入场焦点、Tab/Shift+Tab 限制、背景 inert 或关闭后焦点恢复。遮罩仅阻挡鼠标，aria-modal 不会替代实际焦点控制，原焦点仍可能位于底层操作。AppSheet 的 visible watcher 也不是 immediate，初始即 visible 的实例不会注册对应监听。

最小修复：沿现有组件完成焦点/背景与栈顶 Escape 管理；不引入另一套 UI 框架。等待层要保证未完成时键盘同样不能操作底层破坏性动作。滚动/焦点必须在卸载与多弹层情况下正确恢复。

## DDD 与测试的针对性改进

1. `architecture.spec.ts:15` 只遍历 .ts，仅检查 domain 和 composable 的少数文本模式，未覆盖 Vue SFC、application 对 infrastructure 的依赖、组合根外实例化等规则。扩展现有门禁而非新建平行工具；用违规 fixture 验证检测器自身，避免仅写一堆永远成功的正则。
2. `parity.spec.ts` 只证明 use case 文件存在，不证明功能 parity。保留为文件烟测并明确语义；用上面的关键行为测试承担验收，不靠增加文件名获取信心。
3. 普通可选文本的 mapper 默认值可以保留；对身份 ID、上传会话进度等控制流程字段，需要定点验证。不要直接全项目引入 schema 库。`useFormatDateTime` 对无效时间会抛 RangeError，应在使用到外部空值的路径补安全显示测试；本轮探针开发时无效日期 fixture 实际触发过该异常，但正常后端时间字段尚未观察到此故障，因此不计入 13 项主缺陷。
4. Editor 的页面大小是职责混合信号，不是按行数拆文件的理由。优先把场景提交/保存目标/dirty/取消的不变量定义清楚，再将生命周期编排放进聚焦的 composable/应用会话；选择器和版本列表可在确有独立交互职责时拆组件。
